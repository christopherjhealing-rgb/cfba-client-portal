The public status page

CF Building Approvals — internal reference (Monday-Portal repository)
Reads the board, shows a timeline, needs no login · Updated August 2026

A single public page: reference + site address in, a five-stage timeline out. Unlike the client portal it needs no login, is for anyone holding the paperwork, and writes nothing — it reads the board live. Both fields must match before anything shows, answers are limited to stage + dates + address, and lookups are rate-limited — the site address is what actually protects a job.

What it reads from the board
Ref # The lookup key. A card with a blank Ref # can never be looked up — the client is told "we couldn't match those details" no matter what they type.
Status Decides the stage. Every label maps to one of the five client stages (or to the Cancelled / On Hold card). A label the page doesn't know shows a safe, vague "In progress" — never a guess.
PORTAL Written by the client portal's sync as it delivers — ISSUED → READY → DOWNLOADED, or STUCK. On an issued job this refines the wording ("ready to download in the client portal…"), and STUCK suppresses the Sent date rather than arguing with it. The status page only ever reads it.
Received / Job Sent The dates on the card. A Job Sent cell holding a note instead of a date is never echoed to the client.
When the board changes — the two-minute ritual
  • New or renamed Status label? The page keeps working (the safe "In progress" card) but is vague until the label is mapped. Run npm run inspect, add the label to statusMap in lib/config.js, then npm test — a deliberate test fails until every live label is mapped.
  • New PORTAL label? Same ritual, in CONFIG.delivery. Unmapped there means an issued job says nothing about where its certificate got to.
  • "Wait" is currently an assumption — it appeared on the board Aug 2026 with no jobs carrying it, so the page shows a neutral "Waiting" card. When its real meaning is settled, update the mapping (marked CONFIRM in config).
Board hygiene that shows up here
  • Blank Ref # — the job is invisible to the page. Older cards have these; fill them as they surface.
  • Same ref on two cards (revision, copy) — the page shows the most recently updated one rather than failing the lookup.
  • Item name is the address — a card whose name isn't the site address can't be matched by the client. Keep names as <address> like everywhere else.
