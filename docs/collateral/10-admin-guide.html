The admin front page, top to bottom
  1. 1

    Sync health banner

    Green = last sync ran inside the hour, all good. Amber "stale" = no sync for over an hour — check the incident card. Red "failed" = the error is printed in the banner. Below it, any unmatched Monday clients are listed: those cards' jobs and messages reach nobody until matched. Fix each with the dropdown ("add as alias to…") or New client — one click, done on the next sync.

  2. 2

    Portal pages (the on/off switches)

    Turn a client section off while you update it — the link vanishes, the page shows "temporarily unavailable", and the matching actions pause. Flip it back when done. No deploy needed; takes effect on next page load.

  3. 3

    Info sheets & Council forms

    Upload a PDF to supersede a guidance note (clients get the new version instantly; Revert restores the original), or to host the current BA1/BA2/BA5/BA13/BA19/BA22 under Resources. When the Building Commission revises a form, replacing it here takes ten seconds.

  4. 4

    Submission queue (usually empty)

    Lodgements go straight onto the board. A lodgement only waits here if Monday couldn't be reached when it was submitted — Accept sends it on. If the queue keeps filling, Monday or its token is the problem.

  5. 5

    Run sync

    Forces the 5-minute cycle to run now — useful when a client's on the phone. The result line shows jobs, files, messages and anything unmatched.

Clients & logins
  • Add a client — name as it appears in Monday's Client column (suffixes and brackets are ignored automatically); their email if the board carries it — an email match attaches jobs regardless of spelling; other spellings as aliases.
  • Issue a login — username plus an optional person's name (their messages then show "Joe, Ventura Homes"). The one-time setup code appears once — pass it on straight away; it expires in 30 days.
  • "I can't log in" — click their username to reset: a new setup code is issued and their old password keeps working until they use it. Clients can also self-serve with Forgot password? — a code goes to the email we hold.
  • Check folders — per client, confirms the portal can resolve their SharePoint Issued folders.

Reports and the activity log
  • Reports — issued counts, the actual median turnaround in business days against the 3–4 we publish, and busiest clients. If the median creeps above the published figure, either the process or the promise needs adjusting — the page flags it.
  • Activity log — the append-only record: accepts, rejects, logins issued/reset, client matches, certificate downloads (with who). This is what a complaint, insurer or Building Services Board query asks for — it fills itself.
The messages rules — worth knowing cold
  • An update starting FIR: or CLIENT: goes to the client — portal thread and email. Anything else stays internal. Never start an internal note with either prefix.
  • Works on a card in any active status; completed/cancelled cards aren't scanned.
  • When a client replies, the office gets an email — you never need to watch the board for replies.
  • Files you attach to a Monday update do not reach the client — put requests in words. (Sending documents to clients is a future feature.)
Switches that live in Vercel (not /admin)
AUTO_ACCEPT_LODGEMENTS Default on. Set 0 to make every lodgement wait in the review queue for a human Accept.
DIGEST_ENABLED Default off. Set 1 to send every builder a Monday-morning summary of their active jobs, with a "with you" section that chases FIRs automatically.
RETENTION_MONTHS How long downloaded packages stay before the files purge. Currently 3.
OFFICE_EMAIL Where client-reply notifications land. Keep it a watched inbox.

Changing a Vercel variable does nothing until the project is redeployed — Deployments → ⋯ → Redeploy.

Weekly two-minute sweep
  • Sync banner green?
  • Unmatched list empty — or matched with one click?
  • Submission queue empty?
  • Reports: median turnaround still inside the published 3–4 days?
  • Any new Monday status labels created this week? Tell Chris so the portal's wording map stays complete.
The two calendar reminders that matter: the Microsoft Graph client secret (expires ~July 2028 — six weeks' warning is set; an expired secret silently stops files, folders and email) and the Monday API token if its owner's account ever changes.
