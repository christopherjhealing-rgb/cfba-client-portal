If the portal misbehaves

Symptom → check → fix. In this order, before ringing anyone.
Symptom Check, then fix
Admin banner red or "stale" The banner prints the error. Monday API error → the Monday token (regenerate in Monday → Developers, update MONDAY_TOKEN in Vercel, redeploy). Graph/401/secret → the Microsoft secret has expired: new secret in Entra → GRAPH_CLIENT_SECRET in Vercel → redeploy. No error but stale → Vercel → Settings → Cron Jobs: is /api/sync listed and firing in the Logs?
Client says "no email arrived" 1. Their spam folder. 2. Does the client record hold the right email address? 3. Was the update actually prefixed FIR:/CLIENT:? 4. Remember: an already-sent update never re-emails — post a fresh one. 5. Vercel → Logs → look for "could not email" and read the reason.
Lodgement shows "couldn't save" or waits in the queue Nothing is lost — that message means nothing was recorded, and the queue means Monday was unreachable. Client retries, or Accept it from the queue once Monday's back. Cause in Vercel Logs under "submit failed:".
Live site shows a demo banner SUPABASE_URL didn't take — Vercel → Settings → Environment Variables, fix it, redeploy. Env changes never apply without a redeploy.
Client locked out / forgot password They can self-serve with Forgot password? (code goes to the email we hold). Or /admin → Clients → click their username → reset. Their old password keeps working until the new code is used, so a reset never locks anyone out.
Issued job, but client sees no files 1. Does the card have a reference number? 2. Does the SharePoint folder name end with - <ref>? 3. Client & spelling matched on /admin (not in the Unmatched list)? Fix, then Run sync.
Client messaged but nobody saw it The office reply email goes to OFFICE_EMAIL — is that a watched inbox? The message is also on the Monday card and in the portal thread; nothing is lost.
Status page shows "In progress" instead of a proper stage A Monday status label the page doesn't know — new or renamed. Harmless but vague: tell Chris, or run the label ritual on sheet 25.
Client can't find their job on the status page 1. Does the card have a Ref #? (Blank = invisible.) 2. Is the card's name the site address as they'd type it? 3. Our reference, not the shire's?
Staff sign-in refuses everyone Too many failed passcode attempts trips a ~15-minute cool-off. Protection, not an outage — wait it out. Keeps tripping? Someone's hammering the staff door: tell Chris.
Something's badly broken after a change Rollback is instant and safe: Vercel → Deployments → pick the last good one → ⋯ → Promote to Production. You are never stuck.
Escalation: anything not on this card — grab the exact error text (banner, or Vercel → Logs) and take it to Chris. The error text is the fix nine times out of ten.
Never do these: don't paste the service-role key, Monday token or Graph secret into chat, email or a Monday card — they go straight into Vercel only. Don't make the Supabase issued bucket public. Don't edit DNS records other than adding new ones.
